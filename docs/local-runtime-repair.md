# 本地运行修复设计

状态：已实施；真实站点数据访问等待人工登录验证

## 背景与问题

当前仓库可以解析历史版本的大众点评搜索、详情和评论 HTML，但默认配置包含历史 Cookie，启动时立即初始化 MongoDB，CSV 保存器被禁用，导致 `python main.py --help` 都可能提前退出。代码还存在字符串身份比较、布尔参数解析和不存在配置项等确定性错误。仓库没有自动化测试，无法区分解析能力、程序启动成功和真实站点访问成功。

## 目标

- 使用干净配置在本地安装和启动。
- 默认不携带 Cookie、不使用代理、只请求一页并保存到 CSV。
- `--help`、离线测试和 CSV 保存不依赖 MongoDB。
- 登录重定向、人工验证、超时和 HTTP 错误具有明确且有限的失败结果。
- 为搜索、详情、评论解析和 CSV 保存建立离线回归测试。

## 非目标

- 不绕过登录、验证码、Yoda、H5Guard、设备指纹或其他风险控制。
- 不提供账号池、代理池、接码或自动滑块能力。
- 不保证历史 CSS/字体映射规则仍兼容当前大众点评页面。
- 不进行批量或高频真实站点采集。

## 选定方案与备选方案

选定方案是在现有 Requests/BeautifulSoup 架构内做最小修复：清理示例凭据，默认 CSV，存储器延迟初始化，请求统一超时，将登录与验证转成显式异常，并补充标准库 `unittest` 测试。

备选方案一是迁移到 Playwright，由浏览器承载登录态。该方案更适合后续人工登录，但超出本次“修复现有仓库”的范围。备选方案二是继续要求 MongoDB 和手工修改源码，无法满足开箱启动与可重复验证，因此不采用。

## 影响范围

- `main.py`：无副作用帮助命令、参数解析和退出码。
- `config.ini`、`require.ini`、`cookies.txt`：安全默认值和最小单页运行配置。
- `utils/spider_config.py`：请求超时和 Cookie 状态配置。
- `utils/requests_utils.py`：统一超时、登录/验证识别和有限失败。
- `utils/saver/`：延迟初始化 MongoDB并恢复 CSV 输出。
- `utils/spider_controller.py`：无 Cookie 请求类型及配置名修复。
- `function/`：HTTPS 地址和可预测错误处理。
- `tests/`：离线解析、存储和 CLI 回归。

数据接口仍沿用仓库现有中文字段；CSV 中的嵌套字典和数组使用 JSON 字符串保存。

## 安全、兼容性与合规

- 示例配置不得包含可用 Cookie、Token、代理密钥或 MongoDB 凭据。
- 登录或人工验证只能由用户在官方页面手动完成；程序不会自动处理。
- 默认单页、无代理、带请求超时，避免无限递归和意外批量请求。
- 保留 Python 3.9 兼容性，并约束 `urllib3` 版本以适配系统 LibreSSL。
- 修改后的仓库继续受上游 GPL-3.0 和 README 附加使用声明约束。

## 风险与回滚

真实页面结构和字体规则可能已经变化，即使程序启动正常也可能无法解析当前数据。登录重定向可能在不同地区表现不同。回滚时可恢复本次变更文件；输出仅位于被忽略的 `output/`，不影响原始数据。
